## Next step
1. **Fix the XFB copy vertical filter (brief, one Sonnet session) — cause of the "shake".** Owner: the picture trembles from the first logos (Natsume / Marvelous), not only on the title, and also on a 60 Hz monitor. Captured logo frames are pixel-identical from frame to frame, so nothing actually moves: the tremor is a vertical ghost. Cause found in `src/gfx/gfx_renderer.cpp` (copy pixel shader, around `int y = clamp(sy + k - 3, ...)`): the seven copy-filter coefficients (`vfilter`, observed {8,8,10,12,10,8,8}) are applied to seven different EFB rows (y-3 .. y+3), smearing every line over seven lines with almost equal weights. On the hardware the seven coefficients belong to three rows: 0-1 to the row above, 2-4 to the current row, 5-6 to the row below (the anti-aliasing sample layout: 2 + 3 + 2 subsamples), so the observed set is 16/64, 32/64, 16/64, a light deflicker. Evidence to cite in the note: public GameCube GX documentation of the copy filter (`GXSetCopyFilter` vertical filter, 7 coefficients over 3 lines) and Dolphin's behaviour (read for understanding only, no code copied). Scope: the DX11 copy shader and the CPU reference renderer if it has the same mapping (`src/gx/gx_soft.cpp`), a test with hand-derived expected values (a one-row white line through the filter gives 1/4, 1/2, 1/4 on three rows), the "Decisions in force" line about the deflicker filter stays true (still on by default, now correct). Frame captures change on purpose; the boot trace and `EXIT ... 11135124000 instructions` must not; bench stays at 130% or more.
