Causes, in order: (1) the renderer calls `getenv` four times per draw (`gfx_renderer.cpp`, AWL_GFX_DUMPDRAW / LITPROBE x2 / VPCHECK; about 4,500 draws per frame, 11.5 M in the run): caching them (experiment, reverted) takes the title from 43% to 85%; (2) the capture-comparison call trace is on by default (`--calls 16`): every call up to depth 16 is appended to an unbounded vector for the whole run (window runs included), so memory grows and the copies cost up to half the time; (3) what is left with the renderer on: GPU driver and D3D runtime about 25% (about 20 state calls and 3 Map/Unmap per draw, all re-sent every draw), per-draw string work about 10% (pixel-shader key built and hashed as a `std::string`, `report()` builds a `std::string` per draw), GX core about 20% (2.8 ms per retrace), recompiled code and runtime helpers about 25%.

## Next step
1. **Speed implementation (brief, one Sonnet session).** Goal: the title screen at 100% of real time in the window. Order matters: measure with the bench after each step and stop adding steps once the target is met with margin.
   - **Step 1, call trace opt-in.** `awl-host --calls` defaults to 0; `src/hle/dump_host_memory.ps1` and the capture-comparison command in `docs/research/hle-platform.md` pass `--calls 16` explicitly. Nothing else in the trace changes.
   - **Step 2, bench mode.** `awl-host --bench <retrace>`: DX11 device and renderer offscreen (no window, no pacing, no capture files), runs as usual, and at exit prints one line `speed: retraces A-B, game X s, wall Y s, Z% of real time` measured from retrace A (59.94 Hz fields) to the end. Small change in `host_main.cpp` / `gfx_output.*` (the device is today created only for a window or a capture).
   - **Step 3, renderer per-draw cost** (`src/gfx/gfx_renderer.cpp`, `gfx_shader_cache.*`), each sub-step measured: (a) read every `AWL_GFX_*` debug variable once at renderer start, never per draw; (b) `report()`/`skip()` count by reason without building a `std::string` per call; (c) pixel-shader lookup with a fixed-size key and a cheap hash, and reuse of the previous draw's shader and state objects when the pipeline state did not change (the GX core rebuilds the pipeline on 1.5 M of 13 M draws); (d) state shadowing: call a D3D11 setter only when the bound value differs from the last one set (render target, viewport, scissor, raster, blend, depth, input layout, topology, buffers, shaders, constant buffer, SRVs, samplers); (e) only if still short of the target: update the constant buffer only when its contents change, and batch vertex/index uploads (one Map per batch, flushed before anything that needs ordering: EFB copies, present, texture re-uploads), keeping draw order.
   - **Step 4, only if the bench is below 130% after step 3:** O(1) indirect-call lookup (flat table instead of the binary search in `lookupFunction`), and a fast path for stores to the GX write-gather port (0xCC008000) that skips the generic MMIO dispatch. Out of scope for this block: changing checkpoint granularity or the memory model in generated code (it moves interrupt landing points, a separate decision).
